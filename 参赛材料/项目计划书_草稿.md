## 一、项目概述

### 1.1 背景与痛点

餐饮行业有上千万中国厨师（据公开行业报道口径），但绝大多数人的职业机会依赖熟人引荐。真正的门槛不是手艺，而是**手艺无法被结构化表达**：

- 一位老师傅会做三十六道古早菜，简历却只能写八个字；
- 「你是谁带的」比「你在哪里干过」更重要，但师承关系只存在于口耳相传，无法进入招聘、评价与协作等正式场景；
- 45+ 岁、不擅文书、不会打字的从业者，在主流招聘平台的投递回复率长期低下。

与此同时，厨师行业最底层的信任机制——**师承**——正在快速失传：名门徒弟谱系散落各处，无人数字化，老字号与地方菜系的技艺传承缺少档案。

### 1.2 作品定位

星厨传承把「师承」从隐性人际关系转化为**可记录、可搜索、可匹配的职业基础设施**，同时完成两件公益的事：

1. **助就业**：帮不擅文书的弱势就业群体（45+ 老师傅、学历不高的从业者），用大白话/语音就能生成规范求职档案，让手艺被看见、让每一位厨师有出路；
2. **助传承**：把名门师承谱系数字化为可溯源的开放档案，让老字号与地方菜系的技艺传承有据可查。

### 1.3 核心创新点

**创新一（题材）：以「师承」而非「简历」作为信任底层。**
现有招聘产品以简历字段为核心；本作品把行业中最具约束力、却最难被系统表达的师承关系作为一等数据建模对象：1,238 位真实厨师档案、275 条待补档案、262 位真实厨师录得师承出处、8 个门派 / 43 个菜系分类。

**创新二（数据）：真实、可溯源、宁缺毋滥的数据底座。**
1,238 条真实人物档案中 1,103 条（89.1%）携带原始资料网页链接，853 位有可核查的公开照片；每条师承关系标注置信度（「公开简介推断 · 人工核验持续进行中」）；所有推断信息显式标注「待核实」，所有不完整档案以「待补」徽标诚实呈现——**宁缺毋滥，绝不在界面上编造任何人物、关系或统计数字**。

**创新三（AI）：把口述变成档案，严格按口述提取。**
AI 求职助手让厨师用大白话/语音描述经历，自动生成规范求职档案；提示词层明令「只提取明确说出的信息，严禁编造、推测」，未提及字段如实返回「未提供，可在此补充」，并给出完整度评分与补充引导——AI 在这里不是编故事的，是帮不擅表达的劳动者整理事实的。

**创新四（体验）：功能克制，参与感优先。**
五条动线（首页 → 数字师承谱 → 厨师档案 → 招聘匹配 → AI 求职 → 社区）每一步都可操作、有反馈、有闭环：谱页点一人即点亮一条师承链；档案可点击直接修改并一键复制；社区发帖本机持久化；30 秒一键演示让评委无需配置即可体验全流程。

### 1.4 社会价值

- **对厨师**：手艺获得可携带、可验证、可展示的数字凭证；求职门槛从「会写简历」降为「会说话」；
- **对雇主**：按菜系/门派/师承距离精准筛选，获得可解释的匹配理由（师承 25 分维度的匹配拆解全程可见）；
- **对行业**：技艺传承以数字宗谱形式留存，为非遗申报、老字号振兴提供基础设施级的档案支撑；
- **对社会**：探索「AI 帮助弱势就业群体表达自己」的通用范式——这一范式可平移到木匠、绣娘、理发师等一切「手艺型」职业。

## 二、技术方案

### 2.1 总体架构

```
┌─ 数据层 ──────────────────────────────────────────────┐
│ 公开资料爬取/清洗（scripts/cyxh-*、cswzg-* 等）         │
│ → data/ 来源 JSON（含溯源 URL，宁缺毋滥）              │
│ → data/_merge.js 合并（去重/菜系归一/师承注入）         │
│ → web/scripts/prepare-web-data.mjs（导出+代际重算）    │
└──────────────┬───────────────────────────────────────┘
               ▼
┌─ 应用层（web/ 主交付）───────────────────────────────┐
│ Vite 8 + React 19 + TypeScript + GSAP                │
│ 6 路由：首页/师承谱/厨师档案/招聘匹配/AI求职/社区     │
│ lib/ai.ts：DeepSeek 流式，proxy/直连双模式，         │
│   无 Key 自动降级本地规则演示（界面诚实标注）          │
└──────────────────────────────────────────────────────┘
```

### 2.2 核心模块

| 模块 | 实现 | 关键设计 |
| --- | --- | --- |
| 数字师承谱 | `lib/lineage.ts` + LineagePage | 左栏门派目录（横滑）/中栏代际宗谱/右栏人物档案；点一人点亮整条师承链；跨派学艺 ※ 角标；代际待考折叠+诚实行注 |
| 智能就业匹配 | `lib/jobs.ts` | 菜系 40 + 师门 25 + 师承距离(图上 BFS)15 + 地域 20 + 薪资 15 五维打分；A/B 对比解释「为什么是他不是他」；候选人过滤已故人物 |
| AI 求职助手 | `lib/ai.ts` | DeepSeek 流式；反幻觉提示词（只提取口述事实）；完整度评分与补充引导；剪贴板一键复制档案/自荐信（含非安全上下文 fallback） |
| 厨师社区 | `lib/community.ts` | 按菜系圈子；发帖/评论/点赞 localStorage 持久化；预置内容诚实披露 |
| 命令面板 | CommandPalette + `lib/search.ts` | ⌘K 全局搜索：姓名/拼音/菜系/门派/拿手菜/称号 |

### 2.3 数据可信度体系（本作品的生命线）

1. **可溯源**：每条真实档案携带来源链接（评委可点击验证）；照片仅来自公开资料；
2. **置信度标注**：师承关系 100% 标注「公开简介推断 · 人工核验持续进行中」，无一条宣称人工核实；
3. **待补档案**：师承关系真实但档案不完整者，以「待补」徽标保留（而非丢弃或编造完整档案）；
4. **演示数据隔离**：岗位/薪资等展示匹配逻辑的数据在界面显式标注「演示数据」；
5. **AI 降级诚实**：无 API Key 时自动降级本地规则演示，界面标注「本地演示解析」；
6. **口径一致**：界面所有统计数字（1,238 / 262 / 853 / 43 / 8）与 `chefs.json` meta 同源，无宣传口径。

### 2.4 稳定性设计

- 无 Key / 断网 / 移动端（320px 起 12 档断点）均可完整体验；
- 语音输入（Web Speech API）支持不擅打字的老师傅；
- 字体自托管（294KB 同源 woff2），大陆网络无白屏风险；
- 头像 lazy 加载 + 钢印兜底（照片缺失时以姓氏印章呈现，保持版式完整）。

## 四、演示指引（评委 3 分钟动线）

1. **首页**（5 秒定调）：「记录一门手艺，连接一份工作，以师承为信用」——顶部「LIVE/ARCHIVE」真实数据徽章、公益切口一目了然；

3. **师承谱**：选一人 → 整条师承链点亮 → 「上溯 X 代 · 门下 N 人」→ 点徒弟看「待补」诚实标注；
